# 三种形态（SKU）定义

同一套 agent 内核，按"有没有屏、有没有 4G"分成三档。

| | **M1 独立版** | **M2 在线版** | **M3 轻量版** |
|---|---|---|---|
| 屏幕 | ✅ 自带（4–5" 触摸屏） | ❌ 借手机屏（PWA） | ❌ 借手机屏（PWA） |
| 网络 | ✅ 4G + Wi-Fi | ✅ 4G（设备开热点给手机） | ❌ 无 4G；用手机热点/家庭 Wi-Fi |
| 独立性 | 最高：脱离手机可独立工作 | 高：有网即在线，手机只当显示器 | 低：手机不在身边就离线 |
| 形态 | 胸牌/小手机 | 卡片/胸牌（无屏） | 卡片（最薄最轻） |
| 重量 | 180–220g | 150–180g | 80–110g |
| 续航（10,000mAh 当量） | 6–8h（亮屏）/ 3 天（息屏） | 18–24h 活跃 / 3–5 天待机 | 2–3 天轻度使用 / 5–7 天待机 |
| BOM（估算） | 600–700 元 | 420–500 元 | 250–320 元 |
| 软件复杂度 | 中（要 UI 层） | 低（复用 PWA） | 最低 |
| 适合场景 | 不想掏手机的用户；演示/媒体 | 主力产品：agent 永不掉线 | 极客尝鲜、差旅、隐私优先 |

## M1 独立版

- 硬件：4GB SoC（RK3566/Orange Pi 类）+ 4–5" MIPI 触摸屏 + 4G Cat.4 + 电池/UPS；
- 系统：Buildroot/Armbian + 轻量 Wayland + Chromium kiosk（先复用 PWA），后续再做 LVGL 原生 UI；
- 关键难点：**散热**（密闭胸牌 2–3W）、**功耗**、**屏幕选型**（MIPI 比 SPI 贵但体验好）；
- 不做什么：不自研手机 OS、不做应用商店——那是另一个量级的战争。

## M2 在线版（推荐主力）

- 硬件：4GB SoC + 4G Cat.4 + 电池；**不开屏**，省掉最贵最耗电的部件；
- 网络设计：设备开 Wi-Fi 热点 + 4G 上行（自带 NAT），手机连设备热点打开 `http://10.0.0.1`；
- 价值主张：**agent 永远在线**——手机没电/没信号也能通过设备 4G 收发任务；
- 风险：4G 模块驱动（EC200A/EC25 需 quectel 脚本）、发热、流量成本。

## M3 轻量版

- 硬件：2GB SoC + 电池，无 4G；Wi-Fi 连手机热点或家里路由；
- 定位：**最便宜的验证形态**，也是"隐私优先"用户的选项（不出门就不联网）；
- 限制：手机离开即离线；只适合家里/办公室常驻。

## 软件如何复用

```
cyberbadge-core（三档共用）
├─ agent 内核（任务队列/工具/记忆）
├─ 本地 Web 服务 + PWA
├─ 设备自检与模式开关（/etc/cyberbadge/mode = m1|m2|m3）
└─ 网络层
   ├─ m1/m2: 4G 拨号 + Wi-Fi AP + NAT
   └─ m3:    仅 Wi-Fi client
```

- **v0.1**：任意 Linux 机器即可跑（当前仓库）；
- **v0.2**：M3 硬件验证（借屏 + 热点）；
- **v0.3**：M2 加 4G（在线版）；
- **v0.4**：M1 加屏与 kiosk UI。

## 建议

先做 **M3 验证软件**（最便宜），再做 **M2 做产品**（价值最大），最后做 **M1 做形态**（最贵最难）。
