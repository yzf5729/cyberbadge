# 产品定义 v0.1（草案）

## 一句话

**CyberBadge 是随身携带的个人设备大管家**：一个常驻的 AI agent，带着你的身份与权限，随时调度家里、办公室和云上的电脑、NAS、路由器与网关。

## 它是什么

- 一个**随身**的 agent 宿主（胸牌形态），7×24 在线；
- 一个**统一的控制面**：把异厂商、异协议的个人设备收进同一套工具与策略；
- 一个**可信的执行者**：用你的身份做事，但每一步都可授权、可审计、可撤销。

## 它不是什么

- 不是远程桌面（不搬像素，搬的是任务）；
- 不是又一个智能家居 App（管的是"能干活"的设备，不只是开关灯）；
- 不是把 root 密码撒得到处都是的"万能钥匙"。

## 三层架构

```
┌─ 身份与权限层 ────────────────────────────┐
│ 设备密钥（安全区）/ 分级授权 / 二次确认 / 审计 │
└───────────────────────────────────────────┘
┌─ 连接层 ──────────────────────────────────┐
│ 覆盖网络（Tailscale/WireGuard）+ 各设备连接器  │
└───────────────────────────────────────────┘
┌─ 执行层 ──────────────────────────────────┐
│ agent 工具：SSH / HTTP API / 文件 / 服务 / 日志 │
└───────────────────────────────────────────┘
```

## 权限模型（关键）

"最高权限"不等于"默认 root"。建议：

| 级别 | 能力 | 默认 |
|---|---|---|
| L0 只读 | 状态、日志、文件列表、容量 | 允许 |
| L1 低危写 | 创建任务、下载文件、重启服务 | 单次确认 |
| L2 高危 | 改配置、删数据、关机、改网络 | 二次确认 + 审计 |
| L3 根权限 | 系统级操作、密钥变更 | 白名单设备 + 生物/密码确认 |

所有动作落审计日志（谁、何时、对哪台、做了什么、结果）。

## 设备接入方式

| 设备 | 接入 |
|---|---|
| Linux / macOS | SSH（密钥）或轻量连接器 |
| Windows | OpenSSH + PowerShell 连接器 |
| NAS（群晖/威联通） | 官方 API；无 API 则 SSH |
| 路由器 / 网关 | SSH / HTTP API（OpenWrt、爱快等） |
| 云主机 | SSH + 云 API |
| 智能家居 | 通过 Home Assistant 等桥接，不直接对接 |

## MVP 范围（第一版只做三件事）

1. **看一眼**：设备在线状态、磁盘、负载、服务是否正常；
2. **取/放文件**：在授权目录内上传下载；
3. **跑一条命令**：白名单命令 + 二次确认 + 输出回传。

再加：**审计日志**与**吊销**（丢设备时一键踢下线）。

## 与现有方案的关系

- **Tailscale/WireGuard**：解决"连得上"，我们解决"让它干活"；
- **Home Assistant**：面向家居自动化，我们面向设备运维与文件；
- **Ansible/脚本**：批量执行，我们做"一句话触发 + 审批 + 解释"；
- **MCP 服务**：可作为执行层的一部分，不重复造。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 丢失 = 钥匙丢失 | 硬件安全区 + 远程吊销 + 短时令牌 |
| 权限过大 | 分级 + 二次确认 + 白名单 |
| 设备异构 | 连接器插件化，先支持 3 类 |
| 网络不可达 | 覆盖网络；必要时反向连接 |
| 合规（办公设备） | 只读默认、审批留痕、可关闭 |
| 单点故障 | 任务落到目标机执行，胸牌只做调度 |

## 衡量成功的指标

- 从"想操作"到"完成"的步数（目标 ≤ 2）；
- 每台设备的接入耗时（目标 ≤ 10 分钟）；
- 审计覆盖率（目标 100%）；
- 误操作率与恢复时间。
